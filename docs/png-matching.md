# Manual PNG-driven cross-dataset match review (historical reference)

This document is a *historical record* of how manual review of NBLAST matches was performed during BANC construction. It is no longer the recommended workflow — the paper-version cross-dataset cell-typing pipeline is the iterative **morphology + connectivity annealing** algorithm in `alignment/`, described in the paper Methods §"Automated typing by morphology and connectivity". The PNG-driven review described below was used earlier in the project as a manual-review layer on top of NBLAST-only matching, and the output it produced (per-neuron 2D comparison PNGs in dataset-paired folders) is still part of the dataverse release for reproducibility.

This doc exists so paper readers who encounter "PNG matching" tags in the data (`INVESTIGATE`, `TRACING_ISSUE`, `NO_MIRROR_MATCH`, `NO_MANC_MATCH`, `NO_FAFB_MATCH`) understand where those came from. For the current automated alignment pipeline, see [`alignment/README.md`](../alignment/README.md).

## What the PNG matching pipeline did

For each query BANC neuron, the pipeline produced a side-by-side 2D image (PNG) comparing it to its top NBLAST hits in each target dataset (mirror BANC, FAFB, MANC, FANC, hemibrain, maleCNS). A human matcher reviewed these images in dataset-paired folders and physically dragged matches between a `images/` (candidate) and a `correct/` (verified) directory, with subsequent processing reading the directory layout to push verified matches back to SeaTable.

The matching PNGs are released as `.zip` archives — see [`BANC-project/manuscript/print/banc_data_locations.md`](https://github.com/htem/BANC-project/blob/main/manuscript/print/banc_data_locations.md) for the canonical GCS + Dataverse paths.

## Folder layout (during the matching effort)

The pipeline produced files on HMS-O2 at `/n/data1/hms/neurobio/wilson/banc/matching/` and synced them to the lab fileserver at `/n/files/Neurobio/wilsonlab/banc/matching/`. The lab-fileserver layout was the matcher's working tree.

For each target dataset (mirror / fafb / manc / fanc / hemibrain / malecns), the directory tree was:

```
matching/<target>/
├── images/                     # candidate matches generated by the pipeline
│   ├── <cell_class>/
│   │   └── <cell_side>/
│   │       └── <query_neuron>/
│   │           ├── <query_neuron>_<hit_neuron_1>.png
│   │           ├── <query_neuron>_<hit_neuron_2>.png
│   │           └── ...
├── correct/                    # human-verified matches (drag-and-drop target)
│   ├── <cell_class>/
│   │   └── ...
├── no_match/                   # no acceptable match in this target dataset
├── investigate/                # ambiguous; needs deeper review
└── X_wrong/                    # the match is wrong (tracing issue downstream)
```

`X_wrong` covers any of `axon_wrong`, `dendrite_wrong`, `cellbody_wrong` etc. — the suffix says which feature of the candidate doesn't match.

## Matcher workflow

1. **Matcher** opens the `images/<cell_class>/<cell_side>/<query_neuron>/` folder and reviews every candidate PNG for that query neuron.
2. **Matcher** drags valid matches from the query-neuron folder into the parallel `correct/<cell_class>/<cell_side>/` path.
3. **Matcher** marks the query-neuron folder as complete using Finder colour tags (green = done, etc.).
4. **Maintainer** runs `o2_transfer.sh` (now at `o2/production/o2_banc_results.sh`) to sync `images/` from O2 without disturbing the `correct/` tree.
5. **Maintainer** runs the `bancpipeline` post-processing step that reads the `correct/` tree, parses query-and-hit IDs out of each filename, and pushes the verified match into SeaTable's `banc_meta` table (columns like `fafb_match`, `manc_match`, `mirror_match`, etc.).

The pipeline that generated the PNGs lives at `banc/nblast/banc-*-nblast-images.R` (one per target dataset). The pipeline that consumes the `correct/` directory and writes back to SeaTable lives at `banc/update/banc-update-matches.R`.

## Tags this workflow set on SeaTable (and their meaning)

These tags appear in the `tags` column of `banc_meta` and propagate to the public-released metadata:

- **`INVESTIGATE`** — added programmatically when the query-neuron's PNG was placed in the `investigate/` folder during PNG matching. Flag for deeper manual review. Cleared when `INVESTIGATE_RESOLVED` is set.
- **`TRACING_ISSUE`** (deprecated) — added programmatically when the query-neuron's PNG was placed in an `X_wrong/` folder during PNG matching. Indicates the neuron's reconstruction has a known defect. **Use `TRACING_ISSUE_2` going forward** — the `TRACING_ISSUE` set was not consistently cleared after re-proofreading, so older entries may no longer apply.
- **`TRACING_ISSUE_2`** — successor to `TRACING_ISSUE`. Same semantics, cleaner provenance.
- **`NO_MIRROR_MATCH`** — left-right mirror NBLAST found no acceptable match (PNG placed in `mirror/no_match/`).
- **`NO_MANC_MATCH`** — BANC ↔ MANC NBLAST found no acceptable match.
- **`NO_FAFB_MATCH`** — BANC ↔ FAFB NBLAST found no acceptable match.

(Analogous `NO_*_MATCH` tags exist for FANC, hemibrain, maleCNS.)

## What replaced this for the paper run

The PNG-matching pipeline produced *individual* match decisions. For the paper-published cell-typing assignments, the workflow shifted to the iterative **annealed morphology + connectivity** algorithm in `alignment/`, which:

1. Uses NBLAST as one input channel (initial type hypotheses) rather than the sole signal.
2. Combines with **type-level connectivity centroids** under an annealed weight schedule (α: 0.05 → 0.95 over 80 iterations).
3. Applies **capacity-constrained greedy assignment** so per-type counts respect FAFB left-right variability.

That algorithm produced the paper's 82.7 % holdout accuracy on the right optic lobe (versus 43.9 % NBLAST-only and 65.0 % NTAC). The PNG-driven manual review still exists in the data lineage — its `correct/`-derived decisions populated the seed labels that the algorithm consumes — but the algorithm itself is what makes the final cell-type assignments.

See [`alignment/README.md`](../alignment/README.md) for the algorithm doc.
